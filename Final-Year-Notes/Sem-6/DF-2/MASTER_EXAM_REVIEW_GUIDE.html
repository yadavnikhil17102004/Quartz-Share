3) Chapter-Wise Theory Notes (Full Syllabus)

Chapter 1: Email and Social Media Investigation

Core Theory

  • Email investigation means forensic analysis of email content plus metadata to establish sender identity, transmission path, and intent.
  • Typical use-cases: phishing, financial fraud, harassment, insider threat, business email compromise.

Client vs Server (important compare question)

AspectEmail Client (MUA)Email Server (MTA)
RoleUser-facing appMail routing and delivery system
ExamplesOutlook, Thunderbird, webmail UIExchange, Postfix, Sendmail
Forensic artifactsPST/OST/MBOX, local cachesSMTP/message tracking logs
Value in investigationUser activity and message copiesTransmission proof and log corroboration

Header Analysis (high-yield)

  • Read Received headers bottom to top.
  • Bottom-most Received entry usually points to originating server/IP.
  • Key fields: From, Return-Path, Message-ID, Date, Received, Authentication-Results, X-Originating-IP.

SPF, DKIM, DMARC (must write cleanly)

  • SPF: validates whether sender IP is authorized in domain DNS policy.
  • DKIM: validates integrity via cryptographic signature.
  • DMARC: tells receiver what to do when SPF/DKIM checks fail.

DMARC policy values:

  • p=none (monitor)
  • p=quarantine (spam/junk)
  • p=reject (hard reject)

Theory point to add for extra marks:

  • Start DMARC rollout with p=none, then move to quarantine/reject after report analysis.

Two Methods of Email Tracing (frequent 5-mark)

  1. Header-based tracing (Received chain, originating IP, timezone correlation)
  2. Server-log tracing (Exchange/Postfix logs, Message-ID correlation)

Role of Email Investigation (Q5 5-mark)

  • Establish communication trail
  • Attribute sender origin
  • Detect spoofing/phishing patterns
  • Support admissible evidence in legal proceedings
  • Enforce enterprise policy and compliance

Social Media Theory Points

  • Key challenges: volatility, cloud-hosted data, platform API limits, encryption.
  • Tool examples for theory answers: Magnet AXIOM, Cellebrite UFED, X1 Social Discovery, Maltego.

Chapter 2: Mobile Device Forensics

Need for Mobile Forensics (Q5 option)

  • Smartphones are primary evidence containers: location, communications, media, app data, credentials.
  • Used in cybercrime, financial fraud, insider leaks, and social media crime investigations.

Major Challenges

  • Device and OS fragmentation
  • Encryption (FDE/FBE)
  • Locks and secure enclave protections
  • Remote wipe risk
  • Cloud-sync off-device evidence
  • Anti-forensics (disappearing messages, cleanup apps)

Mobile Data Extraction Techniques (5-mark core)

  • Manual acquisition: screen-level capture only, fast but incomplete.
  • Logical extraction: API/OS-level accessible data, no deep deleted recovery.
  • File-system extraction: broader than logical, often needs elevated access.
  • Physical extraction: bit-level image, best for deleted data recovery.
  • JTAG/Chip-off: specialist and last resort methods.

Logical vs Physical (2-mark favorite)

AspectLogicalPhysical
Access depthUser/API-levelFull storage image
Deleted data recoveryLimitedStrong
ComplexityLowerHigher
Typical useQuick triage and routine extractionFull forensic reconstruction

SQLite in Mobile Forensics (Q4 frequent)

  • Apps store data in SQLite (.db).
  • Deleted rows may survive in freelist pages and WAL/journal files before overwrite.
  • This is why SQLite is a major source for recovering deleted chats/SMS/call records.

Common DB examples:

  • contacts2.db
  • mmssms.db
  • calllog.db
  • msgstore.db

Evidence Extraction Process (good Q2 answer)

  1. Seizure and isolation
  2. Documentation and chain of custody
  3. Preservation (prevent overwrite)
  4. Acquisition method selection
  5. Hash integrity verification
  6. Analysis and reporting

Chapter 3: Multimedia Forensics

Graphics Basics (Q1 and Q2)

  • Raster graphics: pixel-based, resolution dependent (JPEG, PNG, BMP, TIFF).
  • Vector graphics: mathematically defined, resolution independent (SVG, AI, EPS).
  • Metafile graphics: hybrid representation of drawing/pixel elements (WMF, EMF).

Bitmap vs Raster (common confusion)

  • Bitmap is a specific format family term.
  • Raster is the broader category for all pixel-based images.

Lossless vs Lossy Compression (Q3 favorite)

AspectLosslessLossy
Data retentionCompletePartial loss
Typical formatsPNG, TIFF, ZIPJPEG, MP3, AAC
Forensic impactBetter for evidentiary integrityCompression artifacts, possible hidden-data loss

Scoring line:

  • For evidentiary imaging and steganalysis, lossless originals are preferred.

File Carving (Q1 direct)

  • Recovery technique based on header/footer signatures from raw data.
  • Works even when file system metadata is damaged.
  • Example signature memory line: JPEG starts FF D8 and ends FF D9.

Steganography and Steganalysis

  • Steganography hides data in media (often LSB methods).
  • Steganalysis detects hidden content using visual, statistical, and signature-based analysis.
  • Mention tools in theory answer: StegDetect, StegExpose, Stegsolve, Binwalk.

Chapter 4: Cloud Forensics

Basic Concepts (Q4 direct)

  • Cloud forensics = applying forensic principles in cloud-hosted environments.
  • Core challenge: evidence is remote and often controlled by provider.

Service Models and Forensic Access

ModelExampleTypical forensic visibility
SaaSGmail, DriveMostly app-level logs and provider records
PaaSApp Engine style platformsApp/runtime logs, limited host visibility
IaaSVM-based cloud servicesHighest customer control, snapshots possible

Shared Responsibility (important theory point)

  • Security of the cloud: provider responsibility (infrastructure, hardware, hypervisor layer).
  • Security in the cloud: customer responsibility (data, IAM, OS hardening for IaaS workloads).

CSP Investigation Factors (Q3 direct)

  1. Jurisdiction and legal authority
  2. SLA obligations and retention periods
  3. Multi-tenancy constraints
  4. Log availability and integrity
  5. Encryption and key ownership
  6. Chain of custody with provider attestations

Incident First Responder Responsibilities (Q2)

  • Preserve volatile cloud evidence quickly (snapshots/log exports).
  • Collect and preserve audit trails with hash integrity and timestamps.

Major Vendors (Q5 3-mark)

  • AWS: EC2, S3, CloudTrail, GuardDuty
  • Azure: Azure VMs, Blob Storage, Azure Monitor, Sentinel
  • GCP: Compute Engine, Cloud Storage, Cloud Audit Logs

Chapter 5: Virtual Machine and Network Forensics

Type 1 vs Type 2 Hypervisors (Q3 direct)

AspectType 1Type 2
PlacementBare-metalOn top of host OS
Typical useEnterprise/datacenterDesktop/lab/testing
ExamplesESXi, Hyper-V, XenVirtualBox, VMware Workstation
Forensic contextInfrastructure-level analysisEasier artifact handling in host files

Virtual Network (Q1)

  • Software-defined network structure connecting VMs/virtual devices without dedicated physical wiring per logical segment.

Live Acquisition (Q4 direct)

  • Collection from running systems before shutdown to preserve volatile evidence.
  • Why important: RAM-only evidence, live keys, active processes, and active network sessions can vanish after power-off.

Network Security Goal (Q2)

  • Primary goal is CIA triad preservation:
  • Confidentiality
  • Integrity
  • Availability

Honeynet Project (Q5 2-mark)

  • Organized security research effort using honeynets (network of honeypots) to observe attacker behavior, tools, and TTPs.
