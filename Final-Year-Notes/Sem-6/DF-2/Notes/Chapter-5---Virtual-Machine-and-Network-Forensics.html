Chapter 5: Virtual Machine and Network Forensics

Subject: Digital Forensics-2 (CDS-361) Semester: Sem 6 Tags: forensics virtualization network ram-capture

5.1 Virtual Machine Forensics

Virtualization allows multiple Operating Systems (Guests) to run on a single Host.

5.1.1 Hypervisor Types

  • Type 1 (Bare-Metal):
    • Runs directly on hardware (e.g., VMware ESXi, Microsoft Hyper-V).
    • Investigation: Difficult. Requires accessing the hypervisor logs or management console (vSphere) to snapshot VMs.
  • Type 2 (Hosted):
    • Runs as an app on an OS (e.g., VirtualBox, VMware Workstation).
    • Investigation: Easier. The VM is just a file on the Host OS (e.g., .vmdk or .vdi files in C:\Users\Documents\).

5.1.2 Examination

  • Snapshots: Preserve the state of a VM at a specific time. Extremely valuable for seeing “history”.
  • Mounting Images: Forensic tools can mount .vmdk files as if they were physical disks.

5.2 Live Acquisition (RAM Capture)

Capturing volatile memory (RAM) from a running system before pulling the plug. Why? RAM contains:

  • Decrypted passwords/keys.
  • Running processes (Malware often lives only in RAM).
  • Unsaved documents.

Process

  1. Preparation: Use a sanitized USB drive containing the forensic tools (Evidence Collection). Do NOT install tools on the suspect machine.
  2. Capture: Run the tool with Admin privileges.
  3. Output: Saves a .mem or .raw file to the USB drive.

Tools (2024)

  • FTK Imager: Can capture RAM (“Capture Memory”) to a raw file.
  • DumpIt: Simple command-line tool. Fast.
  • Magnet RAM Capture: Free tool by Magnet Forensics.

5.3 Network Forensics

The monitoring and analysis of computer network traffic for the purposes of information gathering, legal evidence, or intrusion detection.

5.3.1 Network Traffic Acquisition

  • Full Packet Capture (PCAP): Recording every packet. Resource intensive but provides the best evidence.
  • Log Analysis: Analyzing Firewall, IDS, or Router logs (NetFlow).

5.3.2 Tools

  • Wireshark: The industry standard for analyzing .pcap files. Allows deep inspection of packet headers (TCP/IP handshake) and payloads.
  • Tcpdump: CLI packet analyzer.
  • Network Miner: Passive network sniffer that extracts files (images, certs) from traffic.

5.3.3 Honeynets

A network set up with intentional vulnerabilities (Honeypots) to invite attacks.

  • Purpose: To study attacker behavior, tools, and Zero-day exploits in a controlled environment.
  • Forensic Value: Any traffic found on a Honeynet is suspicious by definition.

Slip Questions & Answers

Q: Wireshark — top 10 websites visited / accessed from VM

  1. Open Wireshark → capture on relevant interface (or load .pcap)
  2. Statistics → Endpoints → IPv4 tab → sort by Packets (descending)
  3. Or: Statistics → Protocol Hierarchy → drill into HTTP/DNS
  4. For DNS-based resolution: Statistics → DNS → sort by queries
  5. Filter display: dns to see all domain lookups → export as CSV

Q: Indicators of data exfiltration, unauthorized access, malware comms

  • Exfiltration: Large outbound transfers to unknown IPs; unusual protocols (DNS tunneling on port 53, ICMP payload)
  • Unauthorized access: SSH/RDP from unexpected source IPs; failed auth bursts (brute force)
  • Malware C2: Periodic beaconing at fixed intervals; connections to uncommon ports (4444, 1337); JA3 fingerprint mismatches
  • Wireshark filter: ip.dst != [known_internal_range] to isolate suspicious outbound

Q: Filter packets to find suspicious activity in VM

In Wireshark:

ip.dst != 192.168.0.0/16 && ip.dst != 10.0.0.0/8   # external only
tcp.flags.syn == 1 && tcp.flags.ack == 0             # SYN scan
http.request.method == "POST"                         # data submission

Q: Investigate email logs on mail server using forensic tools

  • Linux: /var/log/maillog or /var/log/mail.log (Postfix/Sendmail)
  • Exchange: C:\Program Files\Microsoft\Exchange Server\V15\TransportRoles\Logs\
  • Look for: MAIL FROM, RCPT TO, HELO/EHLO, delivery status codes (250=OK, 550=rejected)
  • Tools: grep, awk, Splunk, or import into Wireshark if SMTP over network

Q: Wireshark — capture and analyze SMTP traffic

Filter: tcp.port == 25  (or port 587 for submission)

Right-click packet → Follow TCP Stream → see full SMTP conversation:

  • EHLO = client greeting
  • MAIL FROM: = sender
  • RCPT TO: = recipient
  • DATA = email content (headers + body)
  • 250 OK = accepted

Q: Extract and decode MIME-encoded email messages

  1. In Wireshark: Follow TCP Stream of SMTP session → copy DATA section
  2. Identify Content-Transfer-Encoding: base64 sections
  3. Decode: echo "base64string" | base64 -d > attachment.pdf
  4. MIME boundary separates parts — look for --boundary_string

Q: IDS (Snort) to monitor traffic from VM

Rules fire on signatures (port scans, known exploits, C2 beacons). Logs: /var/log/snort/alert

Q: Encrypted network traffic analysis in virtualized environment

Cannot decrypt without keys, but can analyze:

  • TLS SNI field (Server Name Indication) — reveals destination hostname even in encrypted traffic
  • Certificate metadata — issuer, validity, self-signed flag
  • Packet size + timing patterns — identify protocol fingerprints (JA3 hash)
  • Volume anomalies — sudden large encrypted transfers
  • For VMs: capture traffic at virtual switch level on host (pre-encryption if TLS terminated at load balancer)

Q: What info from VM log files in crime investigation?

VM logs reveal:

  • Power-on / power-off timestamps → places suspect at keyboard
  • Snapshot creation times → “frozen state” at time of incident
  • Network adapter changes → evidence of network isolation/pivot
  • USB device connections (via host logs)
  • Guest OS crashes or forced shutdowns

VMware .log example entries:

2025-01-15T10:23:01.456Z| vmx| Powering on VM
2025-01-15T14:45:22.123Z| vmx| Snapshot taken: 'Before_Attack'
2025-01-15T18:10:05.789Z| vmx| Powering off VM

Q: Investigate hypervisor logs for unauthorized access / VM timestamps

  • VMware Workstation: vmware.log in VM folder — power events, snapshot history
  • VirtualBox: VBox.log per-VM
  • Hyper-V: Windows Event Viewer → Microsoft-Windows-Hyper-V-Worker and Hyper-V-VMMS
  • Look for: unexpected power-on times, snapshot creation, config changes

Q: Extract VM log files, config files, snapshots for forensic analysis

  • Config: .vmx (VMware) or .vbox (VirtualBox) — contains MAC, RAM, OS, shared folders
  • Disk image: .vmdk / .vdi — mount with FTK Imager or Autopsy as physical disk
  • Snapshots: .vmsd (snapshot tree metadata) + .vmsn (snapshot state)
  • Process: Copy entire VM folder to forensic workstation → hash everything first

Q: Forensic artifacts in VM vs physical machine

Q: Acquire forensic image of host running multiple VMs

  1. Do NOT shutdown — capture RAM first (FTK Imager “Capture Memory”)
  2. Image the host disk with FTK Imager / dd → captures all VM files (.vmdk, .log, .vmx)
  3. Each .vmdk file = one VM disk — load individually in Autopsy
  4. Preserve snapshot files — they contain historical states
  5. Hash everything: md5sum host_image.dd

Q: Network logs to trace host↔VM activity + VM creation/deletion via system logs

Log types:

  • Firewall logs: traffic between host and VMs (NAT/bridge)
  • IDS/IPS logs: alerts triggered by VM traffic
  • Hypervisor event logs: VM lifecycle events
  • OS System logs: Event ID 13002 (Hyper-V VM start), 13003 (stop)

Determine VM created/modified/deleted:

  • Windows: Event Viewer → System → filter by Hyper-V source
  • VMware: vmware.log timestamp of first entry = creation; config .vmx createDate field
  • VirtualBox: VirtualBox.xml in ~/.VirtualBox/ tracks all registered VMs with creation time
