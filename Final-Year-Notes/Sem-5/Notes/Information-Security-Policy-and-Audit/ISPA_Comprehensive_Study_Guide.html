1. Introduction to IS Governance and Auditing

1.1 The Strategic Imperative

CIA Triad - Foundation of all security controls and audit objectives:

PillarDefinitionBreach Example
ConfidentialityInformation accessible only to authorized partiesNx supply chain attack: 6,700 private repositories exposed
IntegrityAccuracy and completeness of dataLedger manipulation in financial systems
AvailabilityInformation available to authorized users when neededNoName057(16) DDoS attacks on Italian infrastructure

1.2 Information Systems Audit Definition

IS Audit: Process of collecting and evaluating evidence to determine whether a computer system:

  • Safeguards assets
  • Maintains data integrity
  • Allows organizational goals to be achieved effectively
  • Uses resources efficiently

Role: “Third line of defense” providing independent assurance to senior management and regulators.

1.3 Evolving Threat Landscape

Sophisticated Threat Actors

Lazarus Group (North Korea):

  • Campaigns: GhostCall, GhostHire
  • Target: Web3 sector
  • Method: Social engineering via fake job offers with malware-laden PDFs
  • Audit Implication: Must audit HR procedures and employee security awareness

Salt Typhoon (China):

  • Target: U.S. telecommunications infrastructure
  • Impact: Millions of users’ data stolen
  • Audit Focus: Network segmentation, access controls in Critical Information Infrastructure

Living off the Land (LotL) Tactics:

  • Use legitimate tools (PowerShell, WMI) for attacks
  • No malicious files to detect
  • Example: FinalDraft malware using Outlook drafts for C2
  • Audit Requirement: Configuration monitoring of legitimate tools, baseline behavior analysis

1.4 TechGlobal Case Study

Profile: Multinational financial services organization Regulations: GDPR, SOX, PCI DSS Infrastructure: Hybrid (cloud + data centers)

Audit Objectives:

  1. Assess IT control effectiveness for customer data protection
  2. Ensure accuracy of financial data processing
  3. Evaluate regulatory compliance
  4. Identify IT governance and risk management improvements

2. IS Auditing Standards and Lifecycle

2.1 Key Auditing Standards

Standard/FrameworkFocusRelevance
ISACA IS Audit StandardsGeneral audit processMandatory requirements for charter, independence, fieldwork, reporting
COBITIT GovernanceCommon language between IT and business; domains: Plan, Build, Run, Monitor
ISO/IEC 27001ISMS114 controls in Annex A for security management
NIST SP 800-53Federal/Critical InfrastructureComprehensive security and privacy control catalog
PCI DSSPayment Card SecurityPrescriptive controls: encryption, firewalls

ISACA Framework Standards

  • S1 (Audit Charter): Defines purpose, responsibility, authority, accountability
  • S3 (Professional Ethics): Auditor independence - cannot design and audit same control
  • S4 (Audit Planning): Risk-based approach; prioritize high-risk areas
  • S7 (Reporting): Objective, clear, constructive
  • S10 (Follow-up): Verify remedial action taken

Phase 1: Planning and Scoping

  1. Understanding the Business: Comprehend mission (e.g., financial services = data integrity paramount)
  2. Risk Assessment: Rank “Audit Universe” by risk factors
  3. Defining Scope: Boundaries critical (e.g., critical systems, processes, data assets)
  4. Resource Allocation: Timeline and skills (e.g., cryptography expert if needed)

Phase 2: Fieldwork and Execution

Evidence Requirements (ISACA S3): Sufficient, relevant, reliable

Techniques:

  • Inquiry: Interview personnel (must be corroborated)
  • Observation: Watch process execution (verify approval workflows)
  • Inspection: Review documents, configurations (firewall rules, password policies)
  • Re-performance: Independently execute control (restore backup to test validity)
  • Vulnerability Scanning/Penetration Testing: Simulate attacks

Computer Assisted Audit Tools (CAATs):

  • Generalized Audit Software (GAS): Filter data, detect duplicates, identify gaps
  • Test Data: Feed valid/invalid transactions to verify application logic

Phase 3: Reporting

Key Finding: TechGlobal weakness - “weak access controls, shared accounts, inadequate password policies”

Report Must Include:

  • Findings: Factual deviation from criteria
  • Risk: Potential consequence of finding
  • Root Cause Analysis: Beyond symptom (lack of tools vs. lack of staff?)
  • Recommendations: Actionable advice (implement MFA, enhance encryption)

Phase 4: Follow-up (ISACA S10)

  • Verify management remedial action
  • If risk accepted rather than fixed, require formal Board approval documentation

Layer 1: Deterrence

  • CPTED (Crime Prevention Through Environmental Design):
    • Natural Surveillance: Open lines of sight
    • Territorial Reinforcement: Fences, signage (public vs. private)
  • Lighting: Psychological deterrent
  • Signage: Legal/psychological warning

Layer 2: Detection

  • Sensors: Motion (infrared, microwave), glass break, door contacts
  • CCTV: Real-time monitoring + forensic evidence; analytics for loitering
  • Alarm Systems: Must trigger 24/7 monitored response

Layer 3: Access Control

  • Mantraps: Two interlocking doors prevent tailgating/piggybacking
  • Biometrics: Fingerprint, iris, retina (high identity assurance)
  • Smart Cards/Badges: Electronic access with audit trail

Environmental Controls:

  • Fire Suppression: Gas-based (FM-200) not water (damages electronics)
  • HVAC: Optimal temperature/humidity
  • Power: UPS and generators for availability

3.2 Logical Security Controls

Access Control Models

ModelDescriptionUse Case
DAC (Discretionary)Data owner decides accessPersonal OS (Windows file permissions)
MAC (Mandatory)OS enforces based on security labelsMilitary/government (Top Secret, Confidential)
RBAC (Role-Based)Access assigned to rolesEnterprise standard (TechGlobal); simplifies administration

Identity and Access Management (IAM)

Authentication Factors:

  1. Something you know: Password, PIN
  2. Something you have: Smart card, RSA token, smartphone
  3. Something you are: Biometrics (fingerprint, Face ID)

Multi-Factor Authentication (MFA): Combine ≥2 factors

  • TechGlobal Recommendation: Implement MFA to address weak access controls

Active Directory (AD):

  • Central directory service for Windows
  • Group Policy Objects (GPO): Enforce fleet-wide settings (password expiry, USB disable)
  • Least Privilege: Minimum access necessary

WARNING

Salt Typhoon breach demonstrates excessive privileges facilitating lateral movement.

Operating System Hardening

PracticeDescriptionExample
Patch ManagementApply security updatesGoAnywhere MFT (CVE-2025-10035) exploited by Storm-1175
Service MinimizationDisable unused services/portsWeb server shouldn’t have Printer Sharing
File PermissionsRestrict access to critical filesLinux chmod ensuring system files not user-writable

4. Operational Controls and Disaster Recovery

4.1 Segregation of Duties (SoD)

Purpose: Prevent fraud and error - no single individual controls all phases of material transaction

Audit Test: Check if developers have production admin access (could insert malicious code)

Mitigation: If staffing insufficient for full SoD, implement compensating controls (enhanced monitoring, logging)

4.2 Logging and Monitoring

SIEM (Security Information and Event Management): Aggregate logs from firewalls, servers, databases

  • Example: 100 failed logins in 1 minute → brute-force attack detection

Audit Requirements:

  1. What is logged: Logins, privilege changes, file access
  2. Log protection: Separate secured server (prevent attacker deletion)
  3. Log review: Logs useless if unreviewed
    • TechGlobal Finding: “Insufficient monitoring and logging”

4.3 Disaster Recovery and Business Continuity

Definitions:

  • Business Continuity (BC): Keep business running during disruption
  • Disaster Recovery (DR): Restore IT systems

Metrics:

  • RPO (Recovery Point Objective): How much data loss is acceptable? (e.g., 1 hour)
  • RTO (Recovery Time Objective): How quickly must systems be back? (e.g., 4 hours)

5. Network Security and Threat Intelligence

5.1 Network Defense Mechanisms

Firewalls:

  • Packet Filtering: Inspect headers (Source/Dest IP, Port) - fast, low security
  • Stateful Inspection: Track connection state (allow inbound only if response to outbound)
  • Next-Gen (NGFW): Layer 7 payload inspection; identify applications, block specific threats

IDS/IPS:

  • IDS (Intrusion Detection): Passive; alerts SOC on attack signatures
  • IPS (Intrusion Prevention): Active; sits in-line, blocks malicious traffic

Network Segmentation:

  • Divide into zones (Guest, Corporate, PCI/Finance, SCADA)
  • Prevents lateral movement
  • Salt Typhoon lesson: Strict segmentation critical in critical infrastructure

5.2 Malware Threat Landscape

Malware TypeDescriptionExample
RansomwareEncrypts data, demands paymentQilin using Linux encryptors in WSL to evade detection
InfostealersSteal credentialsLampion, Meduza targeting banking via phishing
Supply ChainInject into trusted softwareNx attack: malicious npm packages exposing 6,700 GitHub repos

Case Study: FinalDraft and Outlook Abuse

Campaign: FinalDraft malware Method: Abuses Microsoft Outlook drafts for C2

  • Creates draft emails with hidden commands
  • Attacker reads/responds via synced Exchange server

Audit Implications:

  • Monitor internal email traffic for anomalies
  • Disable Outlook macros
  • Implement behavioral endpoint monitoring (detect PathLoader injection)

6. Domains of IT Security

6.1 Application Security and SDLC

Shift Left: Integrate security early in Software Development Life Cycle

Key Practices:

  • Input Validation: Prevent SQL Injection, XSS by sanitizing user input
  • Code Review: SAST (Static Application Security Testing) + manual peer review
  • API Security:
    • Tata Motors breach: Exposed API keys → 70TB data access
    • Audit: API authentication and key management

6.2 Cloud Security

Shared Responsibility Model

Service ModelCustomer SecuresProvider Secures
IaaS (AWS EC2)OS, DataHardware
SaaS (Salesforce)User Access, Data ConfigApp, Hardware

Cloud Audit Focus:

  • IAM roles: No wildcard (*) permissions
  • S3 bucket permissions: Prevent public exposure
  • CloudTrail logs: Audit access and actions
  • Shadow IT Risk: SSA whistleblower - copying data to unmonitored AWS

7. Cryptography and PKI

7.1 Cryptographic Concepts

TypeKey StructureUse CaseExample
SymmetricOne key for encrypt/decryptBulk data (fast)AES for full disk encryption
AsymmetricPublic + Private key pairKey exchange, signaturesRSA, ECC
HashingOne-way functionIntegrity verificationSHA-256

Hash Properties:

  • One-way (cannot reverse)
  • Avalanche Effect: 1-bit change → completely different hash

7.2 Digital Signatures and PKI

Digital Signature Provides:

  1. Authentication: Proof of origin
  2. Integrity: Proof of no tampering
  3. Non-Repudiation: Sender cannot deny sending

Process: Encrypt message hash with sender’s Private Key

PKI (Public Key Infrastructure):

  • System of Digital Certificates and Certificate Authorities (CAs)
  • Binds public keys to identities
  • HTTPS: PKI ensures connection to real bank, not impostor

TEE.Fail Attack

Target: Intel SGX, AMD SEV (Trusted Execution Environments) Method: Side-channel attack via electromagnetic emissions Result: Recovered cryptographic keys

CAUTION

Even hardware-level encryption not infallible - physical security of server hardware remains critical.

When controls fail, the organization must respond.

  1. Preparation: Plan, train, tool up
  2. Identification: Detect breach
  3. Containment: Stop the bleeding (isolate infected VLAN)
  4. Eradication: Remove threat (re-image servers, reset passwords)
  5. Recovery: Restore data, verify functionality
  6. Lessons Learned: Update process

Forensics is the scientific preservation and analysis of evidence. Chain of Custody: Legal document tracking every person handling evidence

  • Broken chain → evidence inadmissible in court

Order of Volatility (Most to Least):

  1. CPU Cache / Registers
  2. RAM (System Memory) - running processes, decryption keys
  3. Network State (Active connections)
  4. Hard Disk / SSD
  5. Remote Logs / Archival Media

“Going Dark” Challenge:

  • Default encryption (BitLocker, iOS encryption)
  • Powered-off device → data may be unrecoverable without password
  • Response:
    • Live Acquisition (capture RAM while running)
    • Cloud Forensics

Conclusion

The IS Audit Journey:

  1. Governance: Adopt frameworks (COBIT, ISO 27001)
  2. Defense in Depth: Layer Physical, Logical, Operational controls
  3. Continuous Audit: Move from annual to real-time monitoring
  4. Resilience: Accept breaches will occur; invest in IR and DR

Ultimate Goal: Not just compliance, but assurance the organization can withstand hostile digital environment and deliver stakeholder value.
