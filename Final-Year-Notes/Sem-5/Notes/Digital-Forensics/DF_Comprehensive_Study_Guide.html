1. Introduction to Digital Forensics

1.1 Defining the Discipline

Digital forensics is the specialized application of computer science and investigative procedures for a legal purpose involving the analysis of digital evidence. Key requirements include:

  • Proper search authority
  • Chain of custody
  • Validation with mathematics (hashing)
  • Use of validated tools
  • Repeatability
  • Reporting
  • Possible expert presentation

1.2 Core Objectives of Forensic Investigation

  1. Identification and Recognition: Identify potential evidence (hard drives, RAM, cloud logs)
  2. Preservation of Evidence Integrity: Non-destructive collection (use write-blockers)
  3. Extraction and Recovery: Recover active, deleted, hidden, and encrypted data
  4. Analysis and Reconstruction: Correlate data points to establish timelines
  5. Presentation and Reporting: Translate technical findings for non-technical audiences

1.3 Evolution of Forensic Science

  • Ad-hoc Phase (1980s-90s): Lack of specialized tools, analysis on original evidence
  • Structured Phase: Introduction of standardized software and write-blockers
  • Enterprise Phase (Current): Massive datasets, pervasive encryption, remote investigations

Locard’s Exchange Principle: “Every contact leaves a trace” - every user interaction leaves a digital footprint.

2. The Cybercrime Landscape

2.1 Computer’s Role in Crime

Computer as the Target

  • Nature: DoS attacks, malware, ransomware, network intrusions
  • Forensic Focus: System evidence - firewall logs, unauthorized accounts, malicious executables
  • Current Threats: LockBit 5.0, Qilin ransomware with double extortion

Computer as the Instrument (Tool)

  • Nature: Fraud, identity theft, cyberstalking, phishing
  • Forensic Focus: User-generated content - emails, chat logs, browser history
  • Example: “Jingle Thief” gift card fraud campaigns

Computer as an Accessory (Incidental)

  • Nature: Device as evidence repository for physical crimes
  • Forensic Focus: Comprehensive data parsing, GPS location data

2.2 Advanced Threat Actors

  • Nation-State Actors: Lazarus (North Korea), Tick (China)
  • Tactics: Living off the Land (LotL) using PowerShell, WMI
  • Steganography: Caminho Loader using LSB steganography in images
  • Supply Chain Attacks: 150,000+ malicious npm packages

Order of Volatility (most to least volatile):

  1. CPU Cache and Registers (nanoseconds)
  2. Routing tables, ARP cache, process tables
  3. RAM - encryption keys, passwords, active connections
  4. Temporary file systems / Swap space
  5. Disk - persistent storage
  6. Remote logging and monitoring data

4.1 Phase 1: Identification and Seizure

Evidence Sources:

  • Mobile phones, tablets
  • External drives, IoT devices
  • Cloud accounts
  • Network routers

Legal Authority:

  • Search Warrant: Judicial order with probable cause
  • Consent: Voluntary permission (can be withdrawn)
  • Subpoena: Demand for records from third parties

4.2 Phase 2: Preservation and Chain of Custody

Chain of Custody: Chronological paper trail documenting:

  • Who collected evidence
  • When and where
  • Every transfer with signatures

WARNING

A broken chain of custody can make evidence inadmissible in court.

Mobile Device Protection:

  • Faraday Bags: Block cellular/Wi-Fi/Bluetooth to prevent remote wipe
  • Follow Order of Volatility for collection

4.3 Phase 3: Acquisition

Acquisition TypeDescriptionProsCons
Physical (Bit-Stream)Complete copy including unallocated spaceMost complete, captures deleted dataTime-consuming, difficult on encrypted devices
LogicalCopy of visible files onlyFast, easy to interpretMisses deleted data and system artifacts
File SystemExtract file structure and system filesMore comprehensive than logicalMay require root/jailbreak
LiveCapture from running systemPreserves volatile data (RAM)Alters system state

Write Blocking: Hardware/software device preventing write commands to source drive.

Cryptographic Hashing: Mathematical validation using MD5, SHA-1, or SHA-256 to prove bit-for-bit copy integrity.

4.4 Phase 4: Analysis

  • Timeline Analysis: Chronological view of file activity
  • Keyword Searching: Search for specific terms, IP addresses
  • Link Analysis: Visualize connections between data points

4.5 Phase 5: Reporting

Must be:

  • Objective and factual
  • Clear for non-technical audiences
  • Document methodology and tools used

5.1 Android Forensics

Architecture:

  • Built on Linux Kernel
  • File Systems: ext4 or f2fs
  • Data Storage: /data/data/<package_name> in SQLite databases

Security:

  • App Sandboxing (each app has unique UID)
  • Full-Disk Encryption (FDE) or File-Based Encryption (FBE)
  • Verified Boot, SELinux

Challenges: Device fragmentation, requires rooting for physical access

5.2 iOS Forensics

Architecture:

  • Based on Darwin Kernel (Unix-like)
  • File System: APFS (optimized for flash, encryption-first)

Security:

  • Secure Enclave: Hardware coprocessor for cryptographic operations
  • Hardware encryption makes physical acquisition difficult
  • Passcode attempts limited by hardware delays

Acquisition Methods:

  • Logical extractions (iTunes backups)
  • Exploits like checkm8 (A5-A11 chips vulnerability)

5.3 Cellular Network Architecture

Key Components:

  • BTS (Base Transceiver Station): Cell tower
  • BSC (Base Station Controller): Manages multiple BTSs
  • MSC (Mobile Switching Center): Routes calls/messages
  • HLR (Home Location Register): Subscriber database
  • VLR (Visitor Location Register): Temporary roaming data

Forensic Value: Cell Site Analysis for location tracking

5.4 SIM Card Forensics

File System Hierarchy:

  • MF (Master File): Root directory (3F00)
  • DF (Dedicated Files): Sub-directories
  • EF (Elementary Files): Actual data

Key Elementary Files:

  • EF_SMS (6F3C): Text messages (deleted messages often recoverable)
  • EF_ADN (6F3A): Contacts
  • EF_LOCI (6F7E): Location information
  • EF_IMSI (6F07): Subscriber identity

Security: PIN protection, A3/A5/A8 algorithms

5.5 Key Mobile Artifacts

  • SMS/MMS: mmssms.db (Android), sms.db (iOS)
  • Call Logs: Call history databases
  • Location: GPS logs, Wi-Fi history, cell tower triangulation
  • App Data: WhatsApp (msgstore.db), Facebook, Uber in SQLite databases
  • EXIF Data: Geotagged photos with location/time metadata

7. Network Forensics and Threat Intelligence

7.1 Network Forensics Principles

Evidence Sources:

  • Packet Captures (PCAP): Full recording of network traffic (Wireshark)
  • Flow Data (NetFlow): Summary metadata (who, what, when, how much)
  • Logs: Firewall, IDS/IPS, Web Proxy logs

7.2 Integration with Threat Intelligence

Indicators of Compromise (IOCs):

  • Known malicious IPs, file hashes, email subject lines
  • Used to search evidence for known threat actors

MITRE ATT&CK Framework: Map forensic artifacts to known adversary tactics

Example: Lazarus Group uses fake job offers (Operation Dream Job) - search for LinkedIn phishing emails

8. Legal Challenges and Future Directions

8.1 “Going Dark” - Encryption Challenge

  • Modern devices encrypt by default (iOS, Android, BitLocker, FileVault)
  • Without user password, physical acquisition yields encrypted noise
  • Forces reliance on:
    • Live acquisition (while user logged in)
    • Cloud backups
    • Exploits

8.2 Cloud Forensics

Challenges:

  • Jurisdiction: Data in different countries
  • Collection: Cannot seize physical servers, must use APIs
  • Requires tools to authenticate and extract cloud data forensically

8.3 Anti-Forensics

Suspect Techniques:

  • Data Wiping: Multiple overwrites to prevent recovery
  • Steganography: Hiding data within other files
  • Obfuscation: Packers to prevent malware analysis

Counter-measures: Dynamic analysis in sandboxes

Recommendations for Exam Preparation

  1. Memorize the 5-phase forensic process
  2. Understand why hashing works and file system structures
  3. Distinguish Android vs. iOS security models and acquisition challenges
  4. Stay current with threat intelligence (ransomware trends)
  5. Practice with both open-source (Autopsy, Wireshark) and commercial tool concepts

Key Takeaways

IMPORTANT

  • Digital forensics requires legal defensibility - every action must be documented
  • Chain of Custody is paramount - any break renders evidence inadmissible
  • Mobile forensics is distinct from computer forensics due to encryption and device diversity
  • Network forensics captures data in motion; disk forensics captures data at rest
  • The future involves cloud forensics, AI analysis, and countering default encryption
